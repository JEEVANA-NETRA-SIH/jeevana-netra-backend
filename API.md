# Jeevana Netra Backend API

HTTP bridge around the compiled MATLAB diabetic retinopathy screening,
explainability and report pipeline.

- Base URL (production): `https://<render-service>.onrender.com`
- Base URL (local): `http://localhost:8000`
- All `/api/*` endpoints may require `X-API-Key` when `JEEVANA_API_KEY` is set (`/health` is always open).
- CORS is restricted to configured origins (production: `https://jeevananetra.vercel.app`).

> Medical disclaimer: AI-assisted prototype. Not a substitute for professional
> medical diagnosis or treatment. AI results are screening support only.

---

## Endpoint summary

| Method | Endpoint | Purpose |
| ------ | -------- | ------- |
| GET | `/health` | Liveness + MATLAB service status |
| POST | `/api/screen` | Analyze a retinal image with the real MATLAB model |
| POST | `/api/screenings` | Persist a real screening result |
| GET | `/api/screenings` | Screening history |
| GET | `/api/patients` | Patient records |
| GET | `/api/patients/{id}` | One patient's screening history |
| POST | `/api/report` | Generate the AI screening PDF report |

Interactive docs: `GET /docs` (Swagger UI) or `GET /openapi.json`.

## GET /health

**Purpose:** Liveness probe and MATLAB availability.

**Request:** none.

**Response `200`:**

```json
{
  "status": "ok",
  "service": "jeevana-netra-backend",
  "matlab": {
    "status": "unavailable",
    "mode": "none"
  }
}
```

`matlab.status` is one of:

- `unavailable` — no compiled MATLAB backend configured/available.
- `configured` — artifact present but no real inference has run yet.
- `initialized` — a real MATLAB inference completed successfully in this process.

The service never claims the model is operational until it has actually run.

## POST /api/screen

**Purpose:** Run the genuine MATLAB screening pipeline (image quality →
preprocess → ResNet-101 DR classification → confidence → referral →
lesion evidence / Grad-CAM) on an uploaded retinal image.

**Content-Type:** `multipart/form-data`

**Parameters (form):**

| Field | Type | Required | Notes |
| ----- | ---- | -------- | ----- |
| `image` | file | yes | PNG or JPEG retinal image, max 20 MB (configurable via `MAX_UPLOAD_MB`). Validated by file signature, not by name. |
| `includeEvidence` | query `?` | no | `true`/`false`, default `true`. Set `false` to skip lesion-explainability (faster, no Grad-CAM). |

**Response `200`** — the field names mirror the MATLAB result structure exactly:

```json
{
  "status": "success",
  "screeningStatus": "SCREENING COMPLETED",
  "qualityStatus": "Good",
  "qualityMessage": "Image quality is suitable for analysis.",
  "predictedClass": "NoDR",
  "confidence": 87.5,
  "confidenceStatus": "HIGH",
  "referralStatus": "NON-REFERABLE DR",
  "recommendation": "No referable DR detected by the AI screening model.",
  "probabilities": {
    "NoDR": 87.5,
    "Mild": 5.0,
    "Moderate": 3.5,
    "Severe": 2.0,
    "ProliferativeDR": 2.0
  },
  "imageQuality": {
    "brightness": 110.0,
    "contrast": 45.0,
    "sharpness": 300.0
  },
  "lesionEvidence": [
    {
      "type": "Microaneurysm",
      "threshold": 0.6,
      "hasEvidence": false,
      "usedPatches": 0,
      "topScore": 0,
      "regions": []
    }
  ]
}
```

**Errors:**

| Status | Meaning |
| ------ | ------- |
| `400` | Not a PNG/JPEG image, or exceeds the upload limit |
| `422` | Missing `image` field |
| `503` | `MATLAB screening service is not configured.` (no compiled artifact) |

**Example (curl):**

```bash
curl -X POST https://<host>/api/screen \
  -F "image=@retina.png" \
  -H "X-API-Key: $JEEVANA_API_KEY"
```

## POST /api/screenings

**Purpose:** Persist a screening result generated by the real MATLAB model
(typically the output of `POST /api/screen`). Creates/updates the patient and
generates a unique screening ID in the format `JN-YYYY-###`.

**Content-Type:** `application/json`

**Request body:**

```json
{
  "patient": {
    "patientId": "P001",
    "name": "Preethi K",
    "age": 45,
    "gender": "F"
  },
  "screening": {
    "predictedClass": "NoDR",
    "confidence": 87.5,
    "confidenceStatus": "HIGH",
    "referralStatus": "NON-REFERABLE DR",
    "recommendation": "...",
    "qualityStatus": "Good",
    "qualityMessage": "...",
    "probabilities": { "NoDR": 87.5, "Mild": 5, "Moderate": 3.5, "Severe": 2, "ProliferativeDR": 2 },
    "imageQuality": { "brightness": 110, "contrast": 45, "sharpness": 300 },
    "lesionEvidence": []
  },
  "screeningDate": "2026-09-21 10:30:00"
}
```

Extra fields (`riskLevel`, `screeningStatus`, …) are accepted and stored when
provided; otherwise they are derived using the same rules as the original
MATLAB patient API (`Mild → Medium`, `Moderate/Severe/ProliferativeDR → High`,
`quality != Good → Pending`, `REFERABLE DR → Requires Review`, else
`Completed`).

**Response `201`:**

```json
{
  "status": "success",
  "operation": "save_screening",
  "patientId": "P001",
  "screeningId": "JN-2026-003",
  "screeningStatus": "Completed",
  "risk": "Low",
  "screeningDate": "2026-09-21 10:30:00",
  "message": "Patient and screening record saved successfully."
}
```

**Errors:** `422` invalid/blank required fields.

## POST /api/report

**Purpose:** Generate the real Jeevana Netra AI screening PDF (2 pages, via the
compiled `jeevana_report_api.m`). Returns the PDF directly by default.

**Option A — JSON** (`Content-Type: application/json`):

```json
{
  "screeningId": "JN-2026-003",
  "patient": { "name": "Preethi K", "id": "P001", "gender": "F", "age": 45 },
  "result": {
    "predictedClass": "NoDR",
    "confidence": 87.5,
    "confidenceStatus": "HIGH",
    "referralStatus": "NON-REFERABLE DR",
    "recommendation": "...",
    "qualityStatus": "Good",
    "qualityMessage": "...",
    "probabilities": { "NoDR": 87.5, "Mild": 5, "Moderate": 3.5, "Severe": 2, "ProliferativeDR": 2 },
    "imageQuality": { "brightness": 110, "contrast": 45, "sharpness": 300 },
    "lesionEvidence": []
  },
  "imageBase64": "<base64 of original PNG/JPEG file bytes>"
}
```

**Option B — multipart:** `image` file + `patient` JSON + `result` JSON +
optional `screeningId`.

**Response** — default `200 application/pdf` with
`Content-Disposition: attachment; filename="Jeevana_Netra_Report_<id>_<ts>.pdf"`.
Use `?format=base64` for a JSON envelope:

```json
{
  "status": "success",
  "filename": "Jeevana_Netra_Report_P001_20260921_103000.pdf",
  "sizeBytes": 123456,
  "pdfBase64": "..."
}
```

**Errors:** `400` invalid base64/image, `415` wrong content type,
`422` missing fields, `503` MATLAB unconfigured, `500` invalid PDF payload.

## Security notes

- Uploads are validated by **magic bytes** (PNG/JPEG signatures), size-limited,
  and handled in memory — never by user filename.
- SQL access uses **parameterized/ORM queries only**.
- Error responses never expose MATLAB tracebacks, filesystem paths or secrets;
  technical details are logged server-side only.
- Optional `X-API-Key` protects all `/api/*` routes when `JEEVANA_API_KEY` is set.
- No database/admin functionality is exposed beyond the documented endpoints.
